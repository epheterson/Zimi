# Zimi 1.9 — the plan

Status: planning. Branch `v1.9`, cut from `main` after 1.8.2 shipped.

## What 1.9 is

Eric, 2026-08-07: "In 1.9 we become a grown up professional app that fits into any setting, a USB drive standalone in a bunker inside a folder of ZIMs that automatically just works. Up to a deployed maintained secure system used by millions. And the dude with a NAS. Ready, for anyone."

One product across that whole range. The range is the feature.

## Decisions already made, do not relitigate

- **One package. No edition gating, no open-core split, no disabled features.** Everything ships on; configuration is what varies. The July plan proposed a paid Industry Edition behind an edition boundary; Eric killed it: "keeping some parts disabled or separate is interesting but also feels like extra baggage, if we could build it lean and integrated we could ship one package." Every gate would be a code path, a test matrix and a support question.
- **Ops and packaging before identity.** An evaluator decides in ten minutes from the README, a compose file and whether `/metrics` speaks Prometheus. SSO is what they need *after* they have decided, and it is the expensive half.
- **Chat with your library stays 2.0.** It is a major-version hero.
- **GitHub Discussions, not Discord.** Chat has to be fed, moderated and staffed to look alive, and none of it is searchable. Discussions sits with the code and every answer becomes a page someone finds later. Needs Eric's go, it is a public surface.

## The compatibility contract

This is a constraint on every workstream below, not a task. Eric: "ensure our existing flow(s) continue to work well, i.e. defining a separate folder and installing normally."

Nothing in 1.9 may change the behavior of an existing install. Specifically:

- `ZIM_DIR` and `ZIMI_DATA_DIR` keep their current meaning and precedence. New flags are additive and lose to explicit environment configuration.
- An existing `<ZIM_DIR>/.zimi` keeps being used where it is. No migration, no move, no prompt.
- Docker keeps `/zims` and `/config`; the NAS compose keeps `/data`. Nothing about a mounted deployment changes.
- The desktop app keeps honoring a configured ZIM folder over anything auto-discovered.
- Auto-discovery only ever fills in a value that was previously a hardcoded fallback (`/zims`, `~/Zimi`). It never overrides a choice a user made.

Every discovery change lands with a test asserting the explicit path still wins.

**Open question, decide before building:** the default state location. Today it is `<ZIM_DIR>/.zimi`, which is what makes a USB stick work and what makes a shared ZIM folder untidy. Eric: "not all folks want a .zimi dir in their zim dir so we need to know what we're doing and make smart defaults." Candidate: keep `<ZIM_DIR>/.zimi` when it already exists or when the ZIM dir is writable and looks self-contained; prefer a platform data dir otherwise; always let `--data-dir` and `ZIMI_DATA_DIR` win. Do not change where any existing install already keeps its state.

## Workstreams

### A. Ops and packaging — "ready to be picked up"

The cheap, high-leverage half. This is what makes someone try Zimi.

- Headless configuration: a config file that fully describes an instance, no click-through setup.
- `--zim-dir`, `--data-dir`, `--host` on `serve`. Today it has `--port` and `--ui`, so everything else is env-only.
- docker-compose and k8s manifests as first-class, documented artifacts.
- Backup and restore: one command to dump and restore config, users, groups, policies, bookmarks. Not ZIMs, those are re-downloadable. Prerequisite for anyone deploying seriously.
- `/metrics` in Prometheus text format so it drops into an existing Grafana stack. Documented healthcheck endpoint. Structured JSON logs.
- Update channels: stable and beta, offline update bundles (download once on a connected box, sideload to the fleet), pinned versions.
- Air-gapped deploy bundle: ZIMs plus image plus config in one tar.
- A deployment page that an evaluator can follow end to end.

### B. Identity and policy

- OAuth2 / OIDC login (Google Workspace, Entra ID, Okta, Keycloak). SAML is the long tail, OIDC first.
- IdP group to Zimi role mapping at login.
- SCIM 2.0 provisioning and deprovisioning, plus CSV/JSON bulk import for air-gapped sites with no live IdP. Both write the same store the light version already owns.
- Per-group ZIM policy above the existing allowlist choke point. A class maps to a shelf, users inherit, individual override optional.
- Forced-login mode: an instance that serves nothing to anonymous visitors.
- Append-only, exportable audit logs. Deliberately distinct from monitoring what someone reads, which stays behind the ethics gate.
- Users-v2 folds in here: emails, self-service reset, kid modes, schools.

### C. Zero-config portable

Bounded. See `2026-08-07-zero-config-portable.md` for the full audit and gap list. The whole feature is four discovery changes plus a portable switch; the architecture already puts state beside the ZIMs, already ships a fully offline frontend, and already degrades rather than fails on read-only media. Do not let this expand.

Two bugs found during the audit, worth fixing regardless of whether portable mode ships:

- `ensure_magnets_for_installed` hits kiwix.org at boot, bypassing the 1.8.2 politeness gate. Once per process, not a standing poll, but the 1.8.2 notes claim zero and that is not currently exact.
- Five data-dir paths are frozen at import and the desktop launcher hand-repairs one, so a custom data dir splits state across two locations.

### D. Owed

- App update checking with per-install-type messaging (#76). Eric asked for this by name. Note the naming collision: "Auto-update" currently means ZIM content refresh.
- Share generated bookmark ZIMs to other devices (#54) — the other half of 1.8.2's export.
- Bookmark view from inside an article (#65).
- Animated calendar jumps (#75).
- Timezone map v3, country borders and labels (#70).
- Delta-T correction for 1920 to 1986 (#80). Moves Chinese calendar day boundaries for a century of real dates, so it needs verification against a reference implementation.
- Regenerate `tz-borders.json` for 13 post-2014 zone changes (#81).
- The Sparkle appcast has no opt-out and dials GitHub on every desktop launch. Both ends of the 1.9 range need to be able to claim no outbound connections.

### E. Positioning

Eric wants this right, and treats it as part of the release rather than a follow-up: README, look, messaging, online placement, and real contributors joining. All three issues closed in 1.8.2 came from one person, which is the whole argument — there are more of them and the only current way in is to file a bug.

## Sequencing

A first, in the order above, because it is cheap and it is what gets Zimi evaluated. C and D interleave, they are small and independent. B is the long pole and starts once A's config and backup story exists, since identity has to be backed up and deployed like everything else. E runs alongside from the start rather than at the end.

## Non-goals

Chat with your library. A paid tier or edition boundary. Discord. Anything that changes how ZIMs themselves are stored or indexed.
