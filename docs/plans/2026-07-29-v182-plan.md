# Zimi 1.8.2 plan — "Follow-through"

A focused polish + community-bugfix dot release on top of 1.8.1, plus the one
real new feature (bookmarks organization) that a user asked for and that pairs
with work already half-built.

Baseline: 1.8.1 shipped 2026-07-28 (all channels live). 1,244 tests.

---

## Wave 1 — Community (tripplehelix, filed against 1.8.1)

### #44 BUG — settings unreachable during initial library load
"The settings button doesn't respond until Zimi has finished its initial load"
(large library; before icons render / Today card fills). Install: uv, v1.8.1.
An errorlog.txt is attached — analyze it first.
- Root-cause: the boot likely blocks the manage/settings entry on the first
  /list or the metadata-load pass (possibly holding a lock, or the UI gating
  interaction until zimsCache populates). Settings/manage must be reachable
  IMMEDIATELY on load, independent of how long the library scan takes.
- Fix: make the settings/manage button live from first paint; if manage data
  isn't ready, open the shell and fill in progressively. Verify with a large
  library (the NAS: 68 ZIMs) that settings opens during the load window.

### #45 FEATURE — bookmarks as a real thing (1.8.2 CENTERPIECE)
Eric expanded this well past "categories." Full scope:
- **Folders, nested** — bookmarks organize into folders and subfolders.
- **Manage interactions** — drag-and-drop to move/reorder; right-click (desktop)
  or long-press (mobile) a bookmark OR folder to move / rename / delete.
- **Tree export** — export all bookmarks, or selected folder(s) with their
  subfolders, chosen from a folder tree: any combination of top-level and
  sub-folders. Each export becomes its own ZIM (medical.zim, research.zim).
- **Generated ZIMs are first-class + shareable** — Eric: "now that we're making
  these zims should we have some way to share them?" Yes. A generated bookmark
  ZIM lands in the library like any ZIM and gets the same sharing rails:
  right-click on the home card AND the … menu in manage → **Download** (the
  existing /dl/ peer endpoint) and **Share** (BitTorrent seed + Nearby/LAN).
  This makes bookmark→ZIM a content-creation-and-distribution flow, not just a
  backup. "This is starting to feel like a real thing." It is — treat it as the
  headline feature.
- Storage reality: bookmarks are per-browser localStorage today; per-user
  server storage landed in 1.8.1 — fold folders into that so a signed-in user's
  organized bookmarks live server-side.

## Wave 2 — Eric's drag-and-drop + 1.8.1 loose ends

### Drag-and-drop drop-rail (task #48)
The 1.8.1 ZIM-onto-category drag is desktop-only (HTML5 DnD, no touch) and
can't reach an off-screen category. Eric told helix he'll take another crack.
- A category drop-strip that appears WHILE dragging (pinned to the viewport
  edge), so you can drop onto any category regardless of scroll position.
- Real touch-drag (long-press-to-lift + pointer events; HTML5 dragstart does
  not fire on touch), so it works on mobile.
- Move to… menu stays as the always-available path.

### Graceful "video not in this ZIM" message (task #43)
Broken-scrape ZIMs (e.g. ted_en_technology, 0-byte video entries) render a page
whose video silently fails. Show a friendly in-player error on <video> error
instead of a dead frame. (Health report already flags these as of 1.8.1.)

### Active-seeds cap with real enforcement (task #45-tracker)
1.8.1 shipped max-concurrent-downloads + max-connections. The active-SEEDS cap
was deferred because libtorrent's auto-managed knobs are inert for Zimi's
hand-managed torrents. Real enforcement = pause lowest-priority seeds past N in
library.apply_seed_policy. Only if it earns a row.

### Auto-dark verification (task #38)
The one pre-1.8.1 check that never ran on real content: confirm auto-dark on a
real infobox-heavy Wikipedia article + a Gutenberg book on the NAS. If it's
rough on either, fix; otherwise close.

## Wave 2.5 — UI batch (Eric field notes, 2026-07-30)

1. **Time Machine to the bottom** of the almanac, and it must NOT bump/jump the
   scroll position when it appears.
2. **Time Machine lever redesign** — "more of a crystal circle looking thing on
   a stick than that." The 1960-Time-Machine crystal-disc-on-a-lever aesthetic,
   replacing the current lever look.
3. **More live-during-travel** — the moon + sky updating live while scrubbing is
   great ("awesome"). Audit every other almanac panel/number and make the cheap
   ones live during travel too: sun & daylight times, orrery planet positions,
   focus date/calendars, meteor-shower countdowns, moon phase %, etc. Keep the
   rAF-throttled budget discipline; skip anything too expensive and say so.
4. **Holidays: full country names** — "Bastille Day · France", not "· FR".
5. **Reader light mode caption contrast** — some wiki pages showed images with
   dark captions in the light reader (dark caption text on/near a dark strip —
   theme-unaware caption styling). Make image captions legible in light.
6. **Home: a tad more padding below the compact/full view picker.**
