# Zimi regression ledger (1.0.0 to 1.10.1)

Every user-facing capability Zimi has claimed to ship, as a checklist a tester can run on a real server, with the test that pins it.

## Sources

- CHANGELOG.md, README.md and docs/features/*.md (access, api-and-mcp, apps, getting-and-sharing, making-zims, operations, reading) as of tag `v1.10.1` (commit 5440e19, which is `origin/main`). The local `main` branch is behind: it stops at the 1.10.0 merge (d3b5948) and has no 1.10.1 entry.
- Tests from `tests/` (pytest files and `*.cjs`, `*.mjs`) and `tests_release/` at the same tag, plus the named jobs in `.github/workflows/ci.yml` where a platform claim is proved only there.

## How to read it

- Claims are merged across releases. "Since" is the release where the current behavior arrived (a later fix to the same claim moves it forward only when the claim changed).
- Test paths are relative to `tests/`. `release/` means `tests_release/` (run by `scripts/release-gate.sh`, not by PR CI). `[gate]` marks those.
- `[manual]` marks a Playwright spec. CI runs `pytest tests/` and every `tests/*.cjs`; it runs none of the 20 Playwright specs, which need a live server and are run by hand. `[manual, stale]` marks `visual_validation.spec.mjs`, which still asserts 1.6.0-era facts (for example `/health` returning version 1.6.0) and would fail today for reasons unrelated to the claim.
- `(all)` means every test in that file or class bears on the claim.
- Coverage:
  - **pinned**: a test would fail if the claim broke. 9 pinned claims rest only on `[manual]` specs (R-28, H-17, SH-31, AC-09, B-02, B-04, B-05, B-06, O-20) and 8 only on the `[gate]` suite (S-01, R-59, AC-30, API-02, API-03, API-05, API-07, API-10); nothing catches those on a pull request.
  - **partial**: a test touches the code but would not catch this claim breaking (checks shape or one half, needs a live library, is excluded from the default run, or is stale).
  - **none**: nothing in the suite exercises it.
- Needs: special data or setup beyond a Zimi server with a Wikipedia ZIM. Blank means any ordinary library will do.

## Findings from the audit

Things that look broken, stale or contradictory in the shipped docs and tests. None were changed.

1. **The catalog-offline guide is wrong.** `docs/features/getting-and-sharing.md` Troubleshoot says "Catalog won't load offline ... With `ZIMI_OFFLINE=1` the catalog is unavailable by design." 1.10.0 shipped a catalog snapshot precisely so it does (L-07), and the README says so.
2. **Nearby's default is described three ways.** README: "Nearby (off by default)". CHANGELOG 1.7.0: "Nearby (LAN sharing) is opt-in, OFF by default ... never a surprise." getting-and-sharing.md: "Discovery is on by default". The code (`p2p_discovery.is_enabled`) advertises on mDNS by default and only the serving half (`is_share_enabled`) is off. A default install announces itself to the LAN, which is what the 1.7.0 promise said it would not do.
3. **`ZIMI_CREATE_ROOT` is documented both ways in one file.** making-zims.md's Configure table says unset means "web off ... the web cannot read any server path"; the same page's prose, the README and `manage.py` say unset means the import picker lists the library folder.
4. **access.md says import is CLI-only "regardless".** Stale since 1.10.0's import picker (C-37). access.md's Configure table also omits `ZIMI_MANAGE_OPEN` and `ZIMI_LAN_ADMIN`, which the README documents.
5. **making-zims.md says "one of four engines" and lists five** (builtin, rendered, alive, singlefile, zimit), then calls them "three bargains" with a three-row table.
6. **getting-and-sharing.md says Home sorts by article count.** #67 (1.9.3) made alphabetical the default with a sort menu (`test_library_sort.cjs` says article count "was the old default").
7. **operations.md: "Data dir not writable, Zimi falls back to a per-library cache dir."** True only for the derived default; an explicit unwritable `--data-dir`/`ZIMI_DATA_DIR` exits 2 (`test_readonly_data_dir.py::test_cli_explicit_unwritable_data_dir_exits_2`).
8. **README's MCP tool list omits the five app tools** (`list_videos`, `list_questions`, `read_question`, `list_posts`, `read_post`) that 1.10.0 shipped and api-and-mcp.md lists. `test_mcp_stdio.py::test_every_documented_tool_is_actually_offered` checks only `docs/integrations/openwebui.md`, so the README can drift silently.
9. **reading.md implies bookmarks and history sync automatically for named accounts**; 1.8.1 and the backup hub test describe an explicit Save to server / Restore from server. One of the two is wrong.
10. **The one-time `/dl/` download ticket (1.9.0 security fix) has no test at all** (`grep -r ticket tests/` is empty). A regression would silently bring back the `.zim.html` download on passworded instances.
11. **1.5.0 says the B-tree index "eliminated FTS5"**; FTS5 is still auto-built and used for multi-word title search (`test_unit.py::TestTitleIndex::test_multiword_search_with_fts5`, 1.7.0's throttle notes).
12. **Stale tests that assert the product's past.** `tests/test_tabs.mjs` drives the tab bar removed in 1.6.1; `visual_validation.spec.mjs` asserts version 1.6.0 and eclipse-era facts; `tests_release/test_04_create.py::test_import_mode_is_a_closed_door_not_a_hidden_one` is named and documented as "import is off the web" (it still passes because it posts a typed path, but it now describes the wrong product).
13. **None of the 20 Playwright specs run in CI.** Every `[manual]` row above, including the private-mode sign-in and admin library ship-blocker specs, is only as good as the last time someone ran it by hand.
14. **Duplicate changelog bullets.** The env panel is announced as new in both 1.9.6 and 1.10.0; 1.7.0 repeats 1.6.4's cherry-picked fixes; the #38 fragment fix appears in both 1.8.0 and 1.8.1.
15. `ZIMI_UPDATE_FREQ` is documented in the README and changes behavior, but no test reads it.
