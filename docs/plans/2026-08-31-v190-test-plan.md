## Part B — your gate (#20), about 30 minutes

### What Part A already found (2026-08-31, before you touched it)

Running A5 against real targets caught two things by hand-testing what the suite could not see. Both are fixed and both have guards now.

**A whole-site crawl of sqlite.org died in 3.1 seconds.** Its homepage builds sponsor logos in JavaScript by concatenating strings that contain HTML, so the page literally holds the characters `<img src='images/…`. We were parsing `<script>` bodies as markup, read a "URL" spanning three lines of JS, and the resulting `http.client.InvalidURL` — an `HTTPException`, not an `OSError`, so `except OSError` missed it — ended the whole job. Both halves fixed: script/style/comment bodies are now masked out of every scan, and no single unusable asset reference can end a job.

**72 of cnn.com's 117 images never painted**, which is your "only the first n images then nothing", measured at last. Every one of the 72 was `loading="lazy"`, 59 of them had a zero-sized box, and there were **zero HTTP failures** — the browser never asked. CNN's homepage is a JavaScript application; without its JS the rails collapse to zero height, and a lazy image in a zero-height container never approaches the viewport, so scrolling can never rescue it. Lazy loading is a bandwidth optimisation for the live web and is pure loss offline, so captured pages now load eagerly.

**Set expectations on CNN specifically:** the Fast engine does not run JavaScript, so a JS-driven *homepage* captures as a shell — 6.8 KB of text, against 63.8 KB for a Wikipedia article. Every image we carried should now paint, but the page will still be much thinner than the live one. That is what the Alive engine is for, and it is the honest answer rather than a bug.

## The thing worth remembering from this release

Nearly every bug that cost us a day was the same shape: **something reported success, or a bound, without checking it.** A pipe that returned `tail`'s exit code. A test runner that exits 0 on a usage error. A release gate that imported a module and called it a test run. A ceiling a subcontractor walked past. A sweep with limits that never said where it was inside them, which fooled our own watchdog before it fooled anyone else.

It happened again while writing this plan: `pytest --timeout=900` with pytest-timeout not installed ran **zero tests** and the harness reported exit code 0.

Fixing the instrument is what found the bugs. That is the habit to keep.
