## Phase 2 — agent-API hardening (Task A)

**`GET /chunks?zim=&path=&size=1200&overlap=120`** — deterministic, embedding-free
chunking of any article, built for RAG clients. No embeddings in-repo (audit rule).

- Clamps: size 200–4000, overlap 0–size/2. Defaults 1200/120.
- Text: the article's stripped text (reuse `strip_html` + the content-fetch path
  in `search.py`). Chunking is paragraph-aware: split on block boundaries, pack
  paragraphs up to `size` chars; oversize paragraphs hard-split at word
  boundaries; each chunk after the first is prefixed with the previous chunk's
  last `overlap` chars. `start`/`end` are char offsets into the stripped text.
- **Stable IDs**: `content_rev` = sha256(stripped_text)[:12];
  chunk `id` = sha256(f"{zim}|{path}|{content_rev}|{seq}|{size}|{overlap}")[:16].
  Same ZIM + params → identical IDs on every server; ZIM update → new IDs
  (RAG cache invalidation for free).
- Response: `{zim, path, title, size, overlap, content_rev, total_chunks,
  chunks: [{id, seq, start, end, text}]}`. 404 unknown zim/path, 400 bad params,
  generic error strings. Rate-limited like /search.
- Core logic lives in `search.py` (has strip_html + archive access); route in
  `http.py`; **MCP tool `get_chunks`** in `mcp_server.py` wrapping the same fn.

**OpenAPI**: hand-authored OpenAPI 3.1 dict in new `zimi/openapi.py`, served at
`/openapi.json` (unauthenticated, rate-limited). Covers /search /suggest /read
/content /list /random /health /chunks with real parameter/response schemas;
`info.version` mirrors the server VERSION.

**API stability contract**: `docs/api-stability.md` — which endpoints are
stable, additive-only JSON policy, deprecation = announced one minor release
ahead.

**Benchmark**: `scripts/bench_agent.py` — times N search→read agent cycles
against a running Zimi; optional `--compare URL` for a kiwix-serve instance.
Run both via Docker with the same small ZIM; write honest methodology +
results to `docs/benchmarks/2026-07-agent-api.md`. If kiwix-serve comparison
proves flaky, ship Zimi-only numbers + methodology and say so.

## Phase 4 — cheap credibility wins (Tasks C, D, E)

- **Task C — "Did you mean" spelling correction** (long-open Kiwix ask,
  libzim#731 class): server-side in `search_all` — when total results < 3,
  suggest a correction from a lazily-built title-word vocabulary (title-index
  terms, capped, cached in memory; `difflib.get_close_matches` or
  edit-distance-1 generation). Additive `did_you_mean` field in /search JSON;
  MCP search passes it through; UI renders a clickable "Did you mean X?" line.
  Fail-soft: no vocab → no suggestion, never an error, never slower than a
  bounded budget (~50ms).
- **Task D — Reader TTS + font scale** (kiwix-js#166 class): reader toolbar
  gains (1) a speak/stop button using the offline Web Speech API
  (`speechSynthesis`) on the iframe article text — hidden when the API is
  absent; (2) an A−/A+ font-size control cycling 85/100/115/130%, injected
  into the iframe document, reapplied on every frame load, persisted in
  localStorage. Both match existing toolbar pill styling; i18n ×10.
- **Task E — Download-this-ZIM button + real article count**: (1) ZIM
  info/manage panel gets a Download action pointing at the existing `/dl/`
  peer endpoint; visibility by capability probe (HEAD /dl/… → 200 show,
  403 hide) so the WAN never sees a dead button. (2) Home/source cards show
  the real article count (libzim `article_count`) instead of raw entry count:
  additive cache field, fallback to entry_count for stale caches (NAS cache
  is NOT deleted; field arrives on natural refresh).

## Addendum (2026-07-21): #37 rolls in — Task J (library organization)

Eric's UX spec, verbatim intent:
- Home right-click on a ZIM card → **Move to…** → assigns the ZIM to another
  category (override). Also a **Reorder sections…** item that deep-links to the
  manage-view reorder panel.
- Library prefs (manage view) → **Reorder sections** option, **collapsed by
  default**, ordering **default categories AND collections in one list**.
- Manage view rows → a gear/dropdown exposing the same Move action (right-click
  alone isn't discoverable).

Design lock-ins:
- Storage: `library_layout.json` in ZIMI_DATA_DIR —
  `{"overrides": {"<zim name>": "<category key>"}, "section_order": ["cat:<key>"|"col:<name>", ...]}`,
  atomic tmp+replace, read fail-soft to empty.
- Reads ride /list additively (effective per-ZIM `category`, top-level
  `section_order`); writes go through auth-gated /manage endpoints (inherits
  the public-locked rules).
- Move targets: the default categories + existing custom ones + free-text
  "New category…". Sections not in the order list append in default order.
- Reorder controls: up/down buttons (mobile-safe, no drag dependency).
