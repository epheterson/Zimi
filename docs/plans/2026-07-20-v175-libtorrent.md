# v1.7.5 — libtorrent migration (design)

**Status:** design, pending review
**Anchor of:** 1.7.5 (catch-up / distribution release)
**Decision owner:** Eric — approved "one engine, everywhere, drop aria2 now" on 2026-07-20

## Goal

Replace the bundled `aria2c` sidecar (out-of-process, driven over JSON-RPC) with
**in-process libtorrent-rasterbar** as Zimi's single BitTorrent engine. BitTorrent
is an *accelerator* for internet/Kiwix-swarm downloads and for seeding; HTTP
remains the universal transport and the universal floor. This migration is about
deleting the accidental complexity that exists only because the engine was a
separate process.

## Why now

`aria2` is a subprocess talking JSON-RPC over a localhost port. Four distinct
"compensation layers" in `p2p.py` exist *solely* because of that out-of-process
model, and every one of them was a real bug we had to patch:

1. **`_spawn_with_fallback` port-walking** (`p2p.py:696`) — an orphaned sidecar
   can squat the RPC port, so we walk +13 ports up to 5 times to find a free one.
   In-process: there is no RPC port.
2. **`is_alive` process-polling** (`p2p.py:720`) — a killed aria2 left the cached
   singleton in place and the UI painted a green dot over a dead engine. In-process:
   the session object cannot zombie.
3. **`followedBy` GID two-phase tracking** (`p2p.py:832`) — a `.torrent`-URL
   download is two GIDs in aria2 (metadata fetch, then content), and reporting the
   wrong one *shipped corrupt, mostly-empty ZIMs*. In-process: one torrent handle
   with a real state enum.
4. **`OPENSSL_MODULES` env hack + session/dht file juggling** (`p2p.py:655`) — the
   relocated bundled libcrypto needs its provider modules pointed at by env, and
   resume/DHT state is persisted through aria2's own `--save-session`/`dht.dat`
   files. In-process: resume data and DHT state are bencoded blobs we own and write
   atomically.

libtorrent also gives us, for free, what aria2-over-RPC made hard: **real per-torrent
stats** (piece progress, true peer/seed counts, upload totals) without polling a
socket, and **fast-resume** that survives restarts without re-downloading.

## Forced architecture: one engine, HTTP underneath

libtorrent **cannot be a hard dependency.** The `libtorrent` PyPI package has patchy
wheel coverage and does not install on this dev machine at all (Python 3.14,
`No matching distribution found`). So the shape is forced, and it happens to match
the fail-soft philosophy the codebase already lives by:

```
tier 1  libtorrent (in-process)   — used wherever `import libtorrent` succeeds
tier 2  HTTP (universal floor)     — used everywhere else; always works
```

There is **no tier for "torrent library missing but we still torrent."** That was
aria2's only real job, and we are deleting it. If libtorrent is not importable on a
platform, torrent is simply off there and downloads/updates use HTTP — slower on
that platform, **never broken**. This is what makes "drop aria2 now" safe: the net
was never aria2, it was HTTP.

`import libtorrent` is attempted once, lazily, guarded. Success → `LibtorrentBackend`.
Failure (ImportError) → `None` → HTTP path, exactly as today when aria2c is absent.

## What gets deleted

- `Aria2Backend` (entire class, `p2p.py:564–906`) and `find_aria2c` (`p2p.py:45`).
- All four compensation layers listed above (they live inside `Aria2Backend`).
- `get_backend_name()` / `ZIMI_BT_BACKEND` selection (`p2p.py:220`, `manage.py:621`)
  — there is nothing left to select.
- The `BTBackend` ABC (`p2p.py:499`) **flattens** into the single concrete
  `LibtorrentBackend`. The *normalized status contract* it documented (the
  `state`/`completed_bytes`/`total_bytes`/`peers`/`ratio`/… dict that `library.py`
  depends on) is preserved verbatim as `LibtorrentBackend`'s documented return
  shape — that boundary is real and valuable; only the one-implementer abstraction
  ceremony around it goes. If a second engine is ever wanted, re-introducing an ABC
  is a 20-line change.
- Desktop aria2 bundling: `zimi_desktop.spec` `ZIMI_ARIA2_DIR` block
  (`zimi_desktop.spec:63–79`), the two "Prepare aria2 sidecar" CI steps
  (`.github/workflows/desktop-release.yml:104–123`), `ci/bundle_aria2_macos.sh`, and
  the aria2c code-signing line.
- Dockerfile `aria2` apt package (`Dockerfile:6`).

Net: roughly −900 lines of engine + compensation + bundling.

## LibtorrentBackend design

One concrete class, in-process, owning a single `lt.session`. Same normalized
surface `library.py` already calls (`add_torrent`, `pause`, `resume`, `remove`,
`status`, `list_managed`, `change_options`, `set_global_rate_limits`, liveness).

**Session lifecycle.** A module-level singleton created on first `get_backend()`.
Settings pack applies the existing knobs: listen port (`get_bt_port`), DHT
(`is_dht_enabled`), global up/down rate limits (`get_bt_*_limit_kb`), UPnP/NAT-PMP
(`is_upnp_enabled` — libtorrent does this natively, replacing the separate
`p2p_nat.py` SSDP dance where libtorrent's is sufficient; keep `p2p_nat.py` for now,
revisit in 1.7.6). No subprocess, no RPC secret, no OpenSSL env.

**Adding.** `add_torrent(source, dest_dir, options)` handles the three source kinds
`library.py` passes today:
- magnet URI → `lt.parse_magnet_uri` + `session.add_torrent`
- `.torrent` *URL* → fetch bytes over HTTP (we already have the download machinery),
  `lt.torrent_info(bytes)`, add. This collapses aria2's two-phase metadata GID into
  one step — the corrupt-ZIM bug (#832) cannot recur because we never report
  "complete" off a metadata fetch.
- local `.torrent` path → `lt.torrent_info(path)`, add.
Returns the info-hash hex string as the stable torrent id (replaces aria2's GID; no
"rebind to followed GID" dance in `library.py:1619`).

**Status.** Read straight off the `torrent_handle` / `torrent_status` — no socket
round-trip. Map libtorrent states to the existing normalized enum
(`downloading`/`seeding`/`paused`/`error`/`complete`). `completed_bytes`/`total_bytes`
from `status.total_done`/`status.total_wanted`; `up_speed`/`down_speed`,
`num_peers`/`num_seeds`, `all_time_upload` for ratio, real ETA. A finished torrent
reports `complete` immediately (so `library.py` installs the file) while the handle
keeps seeding — same semantics as today, but without the `active`+seeder string
remap.

**Resume + continuity.** libtorrent fast-resume data is a bencoded blob per torrent.
Save to `<data>/bt/resume/<info_hash>.fastresume` on the `save_resume_data` alert and
on shutdown; reload on start. **Existing NAS seeders need no migration** — on first
libtorrent start it adds the known torrents pointing at the ZIMs already on disk;
libtorrent hash-checks them (fast, sequential read) and resumes seeding. aria2's old
`bt/session` file is simply ignored and can be deleted.

**Alert loop.** A single daemon thread pumps `session.pop_alerts()` for resume-data
saves, metadata-received, torrent-finished, and errors → updates an in-memory dict
the status calls read. This is the only new thread; it touches nothing libzim, so
the `_zim_lock` invariant is untouched.

## Selection simplification (`get_backend`)

```
get_backend(data_dir):
    if not is_torrent_enabled(): return None          # unchanged
    if singleton: return singleton
    try import libtorrent
    except ImportError: log once, return None          # → HTTP floor
    singleton = LibtorrentBackend(...); return singleton
```

`peek_backend` / `shutdown_backend` keep their signatures. `is_torrent_enabled` and
every UI/env knob (`ZIMI_BT`, seed ratio, mirror, DHT, UPnP, rate limits) are
**unchanged** — they were always engine-agnostic. `manage.py:621`'s backend-name
readout becomes a static `"libtorrent"` (or drops).

## Packaging matrix — the real work

| Target | How libtorrent arrives | Certainty |
|---|---|---|
| Docker / NAS | `apt-get install python3-libtorrent` (Debian ships it; decoupled from pip + Python version) | **High** — lands the mirror win immediately |
| `pip install zimi` | soft optional; not a declared dep. Present → used, absent → HTTP | High (nothing to package) |
| macOS DMG (PyInstaller) | build Python pinned to a version with a libtorrent wheel (3.12); `pip install libtorrent` in the build venv; PyInstaller collects `libtorrent*.so` + boost/openssl deps via hook | **Medium — the tar pit** |
| Linux AppImage (PyInstaller) | manylinux libtorrent wheel for the pinned build Python; collect `.so` + deps | Medium |

The DMG/AppImage rows are where libtorrent migrations stall. Mitigation is structural,
not heroic: **HTTP fallback means a bundling miss on one platform downgrades that
build to HTTP, it does not block the release.** Ship in this order inside 1.7.5:

1. `LibtorrentBackend` + Docker/NAS path + tests. Fast, certain, deploy to NAS, prove
   the mirror seeds/downloads on real ZIMs.
2. Desktop DMG + AppImage bundling. If a platform fights us past a time-box, that
   build ships HTTP-only and we finish bundling in a 1.7.5.x follow-up — the tag is
   never hostage to it.

## Testing

- Unit: state mapping (each libtorrent state → normalized enum), resume-data
  round-trip (save → reload → same torrent), source-kind dispatch (magnet / .torrent
  bytes / local path), rate-limit apply. Mock `lt` where the CI runner lacks it;
  gate the real-engine tests on `import libtorrent` succeeding.
- Integration (Docker CI): add a tiny local .torrent for a fixture file, verify
  download completes and status reports `complete`, verify seeding starts.
- Regression: the corrupt-ZIM guard (old `test_bt_followed_gid`) — reframe as "a
  `.torrent`-URL add never reports complete until content is done."
- The existing `TestClientIPResolution` and unrelated suites must stay green.

## Risks

- **Desktop bundling** (medium) — mitigated by HTTP fallback + staged rollout above.
- **libtorrent API drift** — the Python binding has 1.x vs 2.x differences (settings
  pack, alert categories). Pin a version range; write against 2.0 (current Debian
  stable + wheels), document the minimum.
- **DHT/UPnP behavior change** — libtorrent's native NAT traversal differs from
  aria2's; verify the NAS still becomes reachable (WAN seed) after the switch.
- **Version pin churn** in CI (build Python must have a wheel) — documented, and only
  affects the desktop build job.

## Out of scope (explicitly)

- New backends (qBittorrent/Transmission/Deluge) — the endgame is *fewer* engines.
- Deleting `p2p_nat.py` — libtorrent may fully replace it, but that's a 1.7.6 cleanup.
- Any change to `is_torrent_enabled` / seeding policy / mirror semantics / the UI.
- The rest of 1.7.5 (agent-API hardening, polish batch, cheap wins) — separate specs.
