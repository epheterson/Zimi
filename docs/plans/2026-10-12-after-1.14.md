# After 1.14: where Zimi goes next

Written overnight 2026-10-12 at Eric's ask ("plan our future"), from the plans in this folder, the feature inventory, the issue history and tonight's reviews. A proposal to decide on, not a decree.

## Where things stand

- Shipping fast: 1.11.0 (09-27), 1.12.0 (09-30), 1.13.0 (10-06), 1.13.1 (10-09), 1.13.2 (10-11), 1.14 today. One open issue (#53, which 1.14 closes), no open PRs.
- One tester carries the backlog: tripplehelix filed 32 of the last 40 issues. They are Zimi's QA department, and tonight's goodwill reply matters more than its length suggests.
- Zimi has 7+ apps, 10 languages, an MCP package, Create, BitTorrent with three engines, and 83 GitHub stars. The product has outgrown its audience.
- Tonight four independent reviewers found 30+ real defects in 1.14 before it shipped (a stranger keeping admin after Anyone, anywhere; a client's seeding rule deleting library ZIMs; a switch deleting a finished download). Every one is fixed with a test that fails on the old code. That review step is the single best quality lever this project has found.

## Recommendation: three releases, three themes

### 1.15: Reach (people find Zimi and get it working)

The promises ledger already holds the work; none of it is a new feature.

1. **A 60-second demo** on the README and the release page: search, read, an app, a capture. Recorded by a script so it can be redone each release (see "Fun" below: a first cut exists). Eric on the first cut: some screens are not the best face, the flow can be better, the Almanac stays out (it is the Easter egg), and APOD did not show.
2. **First-run tour:** three cards after setup (search, apps, get more ZIMs), skippable, never again.
3. **The small-model guide:** Zimi + OpenWebUI + MCP with a 3-8B model, the angle dasystemcheck asked about. One doc page plus a tested config.
4. **README rewrite** around the three interfaces (reader, API, MCP) with the demo on top.
5. **Windows installer as the headline download** (decision owed: per-user installer, Authenticode or not).

Success: more stars and more distinct issue reporters than tripplehelix.

### 1.16: Labs (the next app worth building)

- **Labs:** PhET and other interactive ZIMs (114 in the catalog, 7.8 GB) as lesson paths. Eric endorsed it on first read, the content is local, and it is interactive in a way no other app is.
- **The shared details builder first:** books.py and tube.py duplicate it; Labs would be a third copy.
- **Cross-language identity** in Tube, Exchange, Books and Reddot (the biggest known gap in apps already shipped).

### 1.17: Maps as a place (the 1.10 pieces, assembled)

Zimi Maps as one surface with search and places, then travel planning. Routing stays killed.

## Park (with reasons)

- **Community 2.0 and peer chat (ZimiMail, ZimiBee, ZimiChat):** no outside demand yet, heavy moderation, DMCA and identity costs. Revisit when people share Create output and ask for it.
- **Health + Prepared, Khan, Docs, Repair, Arcade, Zimiflix as separate apps:** most fail Eric's own test (the app must beat the ZIM's own pages). Fold Health and Prepared into one task-first view later, or drop them.
- **Almanac additions:** keep it the Easter egg, built alongside, never gating.

## How we work (from tonight)

- **Independent review before every release:** three read-only reviewers (engine, everything else, frontend) on `main...<branch>`, plus a fourth for the next release's research. Findings go into an overnight-style tracking doc; each fix gets a test proven to fail on the old code.
- **A slower, themed cadence:** one release a week with a theme beats one every two days. The inventory grows faster than it ships; themes force the trade-offs.
- **A person-waiting sweep each release:** every issue or thread where someone waits gets a reply in the same release (L3tum waited two months on #53).
- **Drive Eric's path:** NAS first, 390 px phone pass, real end to end (tonight: a real download through qBittorrent behind the VPN).
