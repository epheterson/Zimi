### PR body (v1.14 → main)

Title: 1.14: your own BitTorrent client, Anyone anywhere, zimi doctor

- BitTorrent can use a qBittorrent or Transmission you already run, the way Sonarr and Radarr do (#53): address, login, category, folders. Downloads land in the library and seed there; Zimi's torrents keep their own category and follow Zimi's seed ratio.
- Changing engines takes effect at once: downloads carry on, seeds follow, nothing left behind in the engine you leave.
- The BitTorrent card closes to one line: the engine and whether its port is open or its client connected.
- Who can manage Zimi has a third answer, Anyone, anywhere (#112); while it is on nothing that outlives it can be made. Settings > Server opens on Access.
- `zimi doctor` lists every optional feature, whether it is ready, and how this install gets the rest; CI runs `--check` on a bare pip install and in the image.
- Library and catalog search match titles and descriptions; `source:` finds file names (#108).
- Reviewed by four independent passes before release; 30+ defects fixed, each with a test that fails on the old code.

### #53 reply (L3tum), then close

1.14 is out with this. Zimi can use a qBittorrent you already run, the way Sonarr and Radarr do: Settings > Server > Sharing > BitTorrent, pick qBittorrent, give it the Web UI address, and add folders if the two containers see your downloads at different paths. Or from the environment: `ZIMI_BT_CLIENT=qbittorrent`, `ZIMI_BT_CLIENT_URL=http://gluetun:8080` (wherever its Web UI answers), `ZIMI_BT_CLIENT_PATHS=/downloads=/downloads`. Zimi's torrents go in their own category and it never touches the rest. If qBittorrent can also see your Zimi library, map that folder too and it seeds your ZIMs in place, through the VPN, which covers the CGNAT mirroring you mentioned. Transmission works the same way. Thanks for the idea and the patience; this one took a while.

### Discussion #41 (tripplehelix), close

Closing this out. Since 1.8.1 the engine comes with `pip install zimi` wherever a libtorrent wheel exists (Python 3.13 and older), Docker and the desktop app bundle it, and since 1.14 `zimi doctor` says on any install whether BitTorrent is ready and how to get it. Python 3.14 has no libtorrent wheel yet; 1.14 adds another way for that case: point Zimi at a qBittorrent or Transmission you run.
