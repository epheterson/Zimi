## Drafts (not posted; each needs Eric's go)

### PR body (v1.14 → main)

Title: 1.14: your own BitTorrent client, password off, zimi doctor

- BitTorrent can use a qBittorrent or Transmission you already run, the way Sonarr and Radarr do (#53): address, login, category, folders. Downloads land in the library and seed there; Zimi's torrents keep their own category and follow Zimi's seed ratio.
- Changing engines takes effect at once: downloads carry on, seeds follow, nothing left behind in the engine you leave.
- The BitTorrent card closes to one line: the engine and whether its port is open or its client connected.
- Who can manage Zimi is one switch, Require a password to manage (#112). Turning it off asks for the current password and can be undone. Zimi no longer guesses whether a visitor is on your network. Settings > Users is now Access and holds all of it.
- `zimi doctor` lists every optional feature, whether it is ready, and how this install gets the rest; CI runs `--check` on a bare pip install and in the image.
- Library and catalog search match titles and descriptions; `source:` finds file names (#108).

### #53 reply (L3tum), then close

1.13.3 is out with this. Zimi can use a qBittorrent you already run, the way Sonarr and Radarr do: Settings > Server > Sharing > BitTorrent, pick qBittorrent, give it the Web UI address, and add folders if the two containers see your downloads at different paths. Or from the environment: `ZIMI_BT_CLIENT=qbittorrent`, `ZIMI_BT_CLIENT_URL=http://gluetun:8080` (wherever its Web UI answers), `ZIMI_BT_CLIENT_PATHS=/downloads=/downloads`. Zimi's torrents go in their own category and it never touches the rest. If qBittorrent can also see your Zimi library, map that folder too and it seeds your ZIMs in place, through the VPN, which covers the CGNAT mirroring you mentioned. Transmission works the same way. Thanks for the idea and the patience; this one took a while.

### Discussion #41 (tripplehelix), close

Closing this out. Since 1.8.1 the engine comes with `pip install zimi` wherever a libtorrent wheel exists (Python 3.13 and older), Docker and the desktop app bundle it, and since 1.13.3 `zimi doctor` says on any install whether BitTorrent is ready and how to get it. Python 3.14 has no libtorrent wheel yet; 1.13.3 adds another way for that case: point Zimi at a qBittorrent or Transmission you run.

### #112 reply (tripplehelix)

You were right on this one. 1.13.3 adds it: in Settings > Access, turn off "Require a password to manage" and press Turn off password. It asks for your current password once, keeps it for when you turn the switch back on, and after that nobody is asked for a password from anywhere. Thanks for pushing on it, and for all the reports; most of what's improved lately started as one of yours.

### #108 follow-up (tripplehelix)

A follow-up in 1.13.3: plain words now match titles and descriptions only, so file names stay out of results entirely. `source:` still finds a ZIM by its file name when you want that (`source:nopic`).
