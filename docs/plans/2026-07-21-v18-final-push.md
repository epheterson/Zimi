## Users-v2 backlog (round 2 shipped roles; these are NEXT, do NOT build yet)

Round 2 (this push) shipped: roles (admin / user / limited), secondary admins
with their own manage login, the primary admin shown as a crowned non-deletable
row, the "Username" relabel, and the first-login default-username hint. Parked
for a later Users-v2, in rough priority order:

- **Emails on accounts** — optional email field per user (recovery + identity).
  Storage seam already exists (`flags` dict / new top-level field).
- **Last-login display** — record + surface each account's last login time in
  the users list (sessions.json already stamps `created`; add `last_seen`).
- **Password reset flows** — admin-initiated reset link/code; self-service
  reset needs email first. Today only `set-password` (admin overwrite) exists.
- **Per-user history / bookmarks separation** — history + bookmarks are
  localStorage-only today (per-device). Move to per-account server storage so a
  kid's device and a parent's account don't cross-contaminate.
- **Kid mode / monitoring ethics** — OPEN DESIGN QUESTION (what's acceptable
  worldwide?). Options: read-only history visible to the managing admin, time
  limits, safe-search-only ZIM sets. Must be transparent to the kid (no covert
  surveillance) — decide the ethical line before building.
- **School deployments** — bulk user import (CSV), class/group allowlists,
  shared teacher-admin vs student roles, per-class ZIM bundles.
- **Forced-login mode** — an instance setting that requires a login before ANY
  read (today anonymous = all-access). Turns Zimi from "log in for a restricted
  view" into "no access without an account". Pairs with school/kiosk setups.

Hierarchy note (documented so it isn't relitigated): the PRIMARY admin is the
password-file account and is NOT stored in users.json. Only the primary may
manage admin-role accounts (create/demote/delete) and no admin can mutate the
primary. Secondary admins (role=admin) get all-access + manage but are barred
from touching the primary or other admins. This is the cheapest sane hierarchy;
revisit only if multi-tenant / org-role needs arrive.
