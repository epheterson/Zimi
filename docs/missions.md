# Adding a mission to the Almanac's 3D view

A mission the 3D view plays is fitted to its own record, not drawn by hand. Four pieces, one of each per mission:

1. **Source document**: `scripts/missions/<id>.json`. Every event the record gives: its time (seconds from the mission's zero), the vehicle, the body (`earth`, `moon`), and as much of the state as the record has: latitude, longitude, altitude (nautical miles), space-fixed speed (ft/s), flight-path angle and heading (degrees; heading from the Earth's pole at every body, as the Apollo reports measure it). Each event names its source (`src`, a key of `sources`, with table and page). An event may set its own tolerance (`tol`) and must then say why (`why`).
2. **The fitter**: `scripts/mission_fit.py`. Turns a full event into a state (`report_state`), coasts that land on the next event's state (`coast_to`: the forward coast blended into the backward one, so the path is continuous and passes through every event), burns solved toward their cut-off (`fit_burn`) and small corrections aimed at a later event (`fit_impulse`). The mission's chain (`scripts/mission_<id>_chain.py`) lists the phases in order, each starting from the last one's end; phases with their own physics (a launch, a powered descent, a lunar ascent, an entry) stay in their own modules and take their start state from the chain.
3. **The generator**: `python3 scripts/build_missions.py --only <id>` writes the mission into `zimi/static/earth/missions-v1.json` (the vehicles' legs, phases and events the player reads).
4. **The check**: `python3 scripts/mission_check.py <id>` reads the shipped tables the way the player does and compares every event with the document. `tests/test_mission_events.py` runs it for every document in `scripts/missions/`, so a refit that drifts fails.

Event kinds: a full state (place, height, speed, angles; Apollo 11), `zero` (the mission's own start), `time` and `flyby` (a timeline event of the shipped mission, with a flyby's distance; the Voyagers), `place` (where a vehicle's last leg ends: a lander's pin), `fix` (where a vehicle is on a planet at a time), `site_time` (a landing site's time in sites-v1.json; `scripts/missions/mars_landings.json` is a document of these alone). A time is `t_utc`, or `t_tdb` for a record kept in ephemeris time. An event the 3D view is known to miss carries `open` with the reason: the check reports it, and fails once it is met so the mark comes off.

Steps for a new mission: write the source document from the record; write its chain (reuse `mission_fit.py`, and the phase modules where they fit); build; run the check until every event is within its tolerance; put the record and the fit's constants in the Almanac reference (`almanac-earth.js`, the `ms.` rows).

What a gap means: `mission_apollo11_chain.py` prints, for every link, how far the force model alone lands from the record's next state (the lunar orbit's point-mass Moon drifts a few hundred kilometres over hours, the mascons it leaves out). The blend spreads that gap over the coast; the check is against the record.
